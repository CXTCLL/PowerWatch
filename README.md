# PowerWatch

> 笔记本插着电，却偶发断电一秒又恢复？这个工具专门用来抓这种现场。

Windows 托盘小工具。以 **10 Hz** 持续记录电池电压、充放电电流、交流供电状态与 CPU/GPU 占用；一旦供电发生切换或电压异常跌落，自动把事件**前后各 5 秒**的数据单独存档。

整机 CPU 占用约 **0.18%**，私有内存约 **28 MB**，可长期挂在后台。

---

## 它解决什么问题

笔记本"插着充电器突然断电、约一秒后恢复、完全偶发"这类故障，最难的不是修，而是**抓现场**。

- 去事件查看器查，往往只有一条语焉不详的记录，甚至什么都没有
- 送去维修，工程师当场测不出来，判定"无故障"退回
- 自己观察，等你反应过来去看，事情已经过去了

偶发故障的排查死结在于**证据在发生的那一刻就消失了**。PowerWatch 做的事很简单：把那一刻之前和之后的数据都留下来。

因为你无法预知它什么时候发生，所以只能一直记；因为一直记会占空间，所以它自动只保留最近 3 天。

---

## 适用场景

### 1. 笔记本插电偶发断电，需要抓到证据

典型症状：插着适配器，屏幕黑一下 / 充电图标闪一下 / 键盘背光抖一下，一秒内恢复，无规律。

工具会把 `AC_LOST`（交流丢失）和 `AC_BACK`（交流恢复）两个事件连同前后 5 秒的完整波形存档。拿这份数据可以直接判断：是**功率真的断了**，还是**只是检测信号误判**。

### 2. 充电忽然中断，但机器没有掉电

更隐蔽的一种：系统一直显示"已接通电源"，但电池从充电状态切回放电状态。对应 `CHG_DROP` 事件。这种故障不会让机器重启，所以很多人根本察觉不到，但它往往是供电通路出问题的早期信号。

### 3. 高负载时供电是否跟得上

游戏本在双烤、渲染、编译时，功耗会冲到适配器额定值附近。如果供电通路有接触电阻，电压会随电流明显跌落。工具同时记录 CPU/GPU 占用和电池电压，可以直接看**负载与电压跌落的对应关系**。

### 4. 电池健康与真实功耗评估

连续记录电池电压、电流、剩余容量，比系统自带的"电池报告"细得多。可以看：
- 满电静置时的电压是否明显低于标称值（电芯老化）
- 同样负载下的放电电流是否逐年增大（内阻升高）
- 待机功耗是否异常（后台有东西在跑）

### 5. 送修前的证据准备

板级偶发故障最怕"当场测不出来"。带上：
- `events.csv` 里的事件时间戳
- 对应事件的 `event_*.csv` 快照
- 故障发生时的手机录像

有客观时间点，对方就很难用"没测出来"推回来。

### 6. 换了适配器 / 换了电池之后做对比验证

同一套数据前后对比，比"感觉好像好了"可靠得多。

## 不适用场景

明确划清边界，避免误用：

| 不适用 | 原因 |
|---|---|
| **读取适配器侧的电压和电流** | Windows 没有任何标准接口暴露这个值，详见下方「一个必须说清楚的限制」 |
| **性能监控 / 超频调校** | 10 Hz 采样只够看趋势，抓不到微秒级的瞬时尖峰 |
| **台式机** | 没有电池就读取不到任何电源数据，程序会显示"电池接口不可用" |
| **macOS / Linux** | 全部基于 Windows 原生接口实现 |
| **分析已经发生过的历史故障** | 它只能记录运行期间发生的事，装上之前的历史它看不到 |

## 功能

| 能力 | 说明 |
|---|---|
| 实时监测 | CPU / GPU 占用、电池电压、电池电流、电量、供电状态，界面 5 Hz 刷新 |
| 事件捕获 | 供电切换、充电中断、电压跌落，自动存档前后各 5 秒 |
| 手动打点 | 察觉异常时托盘菜单点一下，立刻留存当前前后 5 秒 |

| 托盘常驻 | 关闭窗口只是收进托盘，继续记录 |
| 开机自启 | 登录后静默驻留，不弹窗 |
| 日志自清理 | 主日志保留 3 天，事件快照 30 天，总量封顶 250 MB |
| 一键安装/卸载 | 免管理员权限，装到用户目录 |

## 数据是怎么读到的

全部走 Windows 原生接口，**零第三方依赖**，没有使用 WMI。

| 指标 | 实现方式 | 为什么这么做 |
|---|---|---|
| CPU 占用 | `GetSystemTimes` 差分 | 比性能计数器便宜两个数量级 |
| GPU 占用 | PDH `\GPU Engine(*)\Utilization Percentage` | 走 `pdh.dll`，不引 NuGet、不装 NVML，A 卡 N 卡通用 |
| 电池电压 / 电流 / 容量 | `IOCTL_BATTERY_QUERY_STATUS` 直接问电池管理芯片 | 单次查询微秒级；WMI 查询要几毫秒，10 Hz 下自身开销就会干扰观测 |
| 交流/电池状态 | `CallNtPowerInformation(SystemBatteryState)` + `GetSystemPowerStatus` 交叉验证 | 两个来源互相印证，避免单一信号误判 |

采样循环用 `Stopwatch` 对齐漂移，实测抖动 **91–110 ms**，均值 100.0 ms。

## 一个必须说清楚的限制

**Windows 不向用户程序暴露适配器侧的输入电压和输入电流。**

方口 / USB-C 进来那 20V 的实际值，系统里没有任何标准接口能读到——要测它得用钳形表，或者在适配器输出线上串一个采样表。

所以界面上「供电电压 / 供电电流」两格标注了**推算**，取的是外接供电时**电池端**的实测值：

- 充电时约等于充电电压 / 充电电流
- 未充电时电流显示 0

它们能回答"供电还在不在"，但回答不了"适配器到底输出了多少瓦"。

**看到 0 mA 不要当成异常**——那是电池满电、系统直接吃适配器、电池支路没有电流的正常状态。

## 日志

全部落在安装目录的 `logs\` 下。

| 文件 | 内容 | 保留 |
|---|---|---|
| `run_yyyyMMdd_HHmmss.csv` | 全程连续记录，每秒 10 行 | 3 天 |
| `event_*.csv` | 单个事件前后各 5 秒的快照，约 100 行 | 30 天 |
| `events.csv` | 所有事件的时间线 | 永久（很小） |
| `recovered_*.csv` | 上次异常关机时抢救下来的日志尾部 | 30 天 |

表头（UTF-8 带 BOM，Excel 直接打开不会乱码）：

```
时间,毫秒,CPU占用%,GPU占用%,电池电压mV,电池电流mA,电池功率mW,剩余容量mWh,电量%,交流在线,充电中,放电中,电源状态
```

| 列 | 含义 |
|---|---|
| 时间 / 毫秒 | 时刻，精确到毫秒；毫秒为程序启动以来的毫秒数 |
| 电池电流mA | **负 = 充电，正 = 放电** |
| 交流在线 / 充电中 / 放电中 | 1 / 0 |
| 电源状态 | 电池驱动原始状态位：`0x0001` 在线、`0x0002` 放电、`0x0004` 充电、`0x0008` 电量危急，可同时置位（如 `0x0005` = 在线 + 充电中） |

### 事件类型

| 代号 | 含义 | 触发条件 |
|---|---|---|
| `AC_LOST` | 交流供电丢失 | 供电状态从在线变为离线 |
| `AC_BACK` | 交流供电恢复 | 反向变化 |
| `CHG_DROP` | 充电中断但交流仍在线 | 电池由充电切为放电，而 `ac` 位不变 |
| `VSAG` | 电压跌落 | 300 ms 内下跌超过 300 mV（状态切换后 4 秒内不判，避开表面电荷弛豫） |
| `MANUAL` | 手动快照 | 托盘菜单手动触发 |

## 怎么用这些数据判断故障

打开事件快照，只看断点那一行附近的 **`batt_mv`** 和 **`ac`** 两列：

```
batt_mv 同时塌下去        → 功率通路上有东西在掉（焊点、保险、MOS）
batt_mv 稳，只有 ac 翻转   → 检测回路误判（ACDET 分压、充电 IC）
两列都毫无变化            → 不是供电事件，方向要换到屏幕背光或显卡驱动
```

更完整的板级排查思路见 [`docs/供电故障排查思路.md`](docs/供电故障排查思路.md)。

## 安装

下载 `PowerWatch-Setup.exe` 双击安装即可，**不需要管理员权限**。

安装到 `%LOCALAPPDATA%\Programs\PowerWatch`，会创建开始菜单快捷方式、注册开机自启、并在「应用和功能」里登记卸载入口。

卸载：安装目录里的 `Uninstall.exe`，或「应用和功能」里搜索 PowerWatch。

> 仓库只包含源码，安装包需要自行构建（见下）。

---

## 从源码构建

需要 [.NET 10 SDK](https://dotnet.microsoft.com/download)。

```powershell
# 项目根目录执行，会先生成主程序再打进安装包
powershell -ExecutionPolicy Bypass -File build.ps1
```

产物在 `dist\PowerWatch-Setup.exe`。

单独编译主程序：

```powershell
dotnet build PowerWatch\PowerWatch.csproj -c Release
```

## 已知限制

- 适配器侧电压电流无法读取（见上文），这是接口限制不是实现问题
- GPU 占用是 3D + Compute 引擎之和，核显独显同时工作时会累加，已截断到 100%
- 采样 10 Hz，无法反映毫秒级以下的瞬态
- 安装包未做代码签名，首次运行可能触发 SmartScreen 提示
