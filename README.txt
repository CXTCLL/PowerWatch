PowerWatch · 供电瞬断监测器　v1.1
================================================================

【安装】
双击 PowerWatch-Setup.exe，勾选需要的选项，点「安装」。

安装不需要管理员权限，文件写到：
    %LOCALAPPDATA%\Programs\PowerWatch

目录里一共五个文件：
    PowerWatch.exe            主程序
    PowerWatch.dll            程序主体
    PowerWatch.deps.json      运行时依赖清单
    PowerWatch.runtimeconfig.json  运行时配置
    Uninstall.exe             卸载程序（双击即可卸载）

装完会在这些地方留下痕迹：
    · 开始菜单快捷方式
    · 注册表 HKCU\...\Run 里的开机自启项（登录后静默驻留托盘）
    · 「应用和功能」里的卸载入口，可搜索 PowerWatch

【日常使用】
安装后程序常驻托盘，**关闭窗口不会退出**，只是缩回托盘继续以 10Hz 记录。
第一次缩回时会弹一次气泡提示，以后不再打扰。

托盘图标双击 = 打开主窗口
托盘图标右键：
    打开主窗口
    立即保存快照      ← 手动打点，5 秒后生成前后各 5 秒的快照
    打开日志目录
    开机自动启动      ← 随时可开关，改的是注册表，立即生效
    清理旧日志
    退出              ← 真正退出程序

托盘图标颜色跟随供电状态：绿色=外部供电，橙色=电池供电。
鼠标悬停能看到当前电压。

【日志自动清理】
程序启动时清理一次，之后每小时清理一次：
    run_*.csv        保留 3 天（这是占空间的主力，约 55MB/天）
    event_*.csv      保留 30 天（每个约 8KB，是证据，留久一点）
    recovered_*.csv  保留 30 天
    总量硬上限       250MB，超了就从最旧的 run 日志开始删
状态栏右下角随时显示当前日志目录占用了多少。

【卸载】
方式一：打开安装目录，双击 Uninstall.exe
        %LOCALAPPDATA%\Programs\PowerWatch\Uninstall.exe
方式二：「应用和功能」里搜索 PowerWatch，点卸载
方式三：命令行运行  PowerWatch.exe --uninstall

会自动关闭正在运行的实例，然后清理程序文件、开机自启项、开始菜单快捷方式、
注册表登记，连安装目录一起删掉。卸载过程会写日志到 %TEMP%\powerwatch_uninstall.log，
万一有残留可以照着日志查是哪一步没成功。

----------------------------------------------------------------
几个必须说清楚的点
----------------------------------------------------------------
1. 适配器侧的电压和电流，Windows 没有标准接口能读到。
   「供电电压/供电电流」两格标注了"推算"，取的是外接时电池端的实测值：
   充电时约等于充电电压/充电电流，未充电时显示 0。
   看到 0 mA 不要当异常——那是电池满电、系统直接吃适配器、
   电池支路没有电流的正常状态。要测适配器实际输出，只能用钳形表。

2. 电池电流的符号以驱动状态位为准，不采信 Rate 字段的正负。
   实测这台机器的驱动在充电时 Rate 仍报正数，若直接采用会把充电显示成放电。
   现在：负数=充电（绿色），正数=放电。

3. 采样间隔 100ms，实测抖动 91–110ms。
   连续记录每秒 10 行，事件快照约 100 行。

----------------------------------------------------------------
日志文件（%LOCALAPPDATA%\Programs\PowerWatch\logs）
----------------------------------------------------------------
run_yyyyMMdd_HHmmss.csv   全程连续记录
event_*.csv               事件前后各 5 秒的快照
events.csv                所有事件的时间线
recovered_*.csv           上次异常断电时抢救下来的日志尾部

列的含义（表头已中文化，直接双击用 Excel 打开就行）：
  时间        时刻，精确到毫秒
  毫秒        程序启动以来的毫秒数，用来算精确采样间隔
  CPU占用%    CPU 占用率
  GPU占用%    GPU 占用率（3D + Compute 引擎合计）
  电池电压mV  电池端电压
  电池电流mA  负 = 充电，正 = 放电
  电池功率mW  负 = 充电，正 = 放电
  剩余容量mWh 电池当前剩余容量
  电量%       电量百分比
  交流在线    1 = 适配器在线，0 = 离线
  充电中      1 = 正在充电
  放电中      1 = 正在放电
  电源状态    电池驱动返回的原始状态位，十六进制
              0x0001 在线 / 0x0002 放电 / 0x0004 充电 / 0x0008 电量危急
              多个位会同时置位，比如 0x0005 表示"在线 + 充电中"

----------------------------------------------------------------
会自动记哪些事件
----------------------------------------------------------------
AC_LOST     交流供电丢失
AC_BACK     交流供电恢复
CHG_DROP    仍报交流在线，但电池从充电切到放电（最隐蔽的一类）
VSAG        300ms 内电压跌落超过 300mV
MANUAL      你手动打点的快照

----------------------------------------------------------------
怎么用这些数据判断故障
----------------------------------------------------------------
中断发生后，先看那一刻的 batt_mv 和 ac 两列：

  batt_mv 同时塌下去        → 功率通路上有东西在掉（焊点、保险、MOS）
  batt_mv 稳，只有 ac 翻转   → 检测回路误判（ACDET 分压、充电 IC）
  两列都毫无变化            → 不是供电事件，方向要换到背光或显卡驱动

如果整机直接掉电没来得及写快照，重启后到 logs 里找 recovered_*.csv，
那里是掉电前最后一段记录。

资源占用（实测）
----------------------------------------------------------------
整机 CPU 0.18%（3.59% 单核 ÷ 20 逻辑核）
私有内存约 28MB，工作集 70–85MB
窗口缩到托盘后不再刷新界面，开销进一步下降
